# T044 PDF 管理页新增导出 Markdown（已完成 2026-11-23）

## 任务目标

在 PDF 管理页新增「导出 Markdown」功能区（REQ/DES-PDF-002）：自建映射管线（复用 PdfPageLayoutAnalyzer → GFM），三级标题判定，图片双模式，图片型 PDF 拒绝并提示。

## 拍板记录（2026-11-23）

- 技术路线：自建映射管线，零新增依赖（调研结论见记忆 azrngtools-pdf-to-markdown-research）。
- 标题策略：用户拍板「三级兜底」——书签坐标 → 结构标签（H1~H6）→ 字号兜底（强约束）。
- 入口形态：用户拍板「并入 PDF 管理页」——右列第三功能区，无 md 预览区，反馈与分割/导出 Word 同口径。
- 扫描件：用户要求图片型内容不处理、直接提示（文档级判定：平均每页 letters < 10）。

## 实现要点与坑位

- **书签坐标双坑**（端到端实证）：PdfPig `Destination.Coordinates.Top` 是 PDF 用户空间自页底 y **且指向标题行顶边**——须 `页高 − Top` 转距页顶口径后与 `行Top − 行高`（顶边）匹配；直接按行 Top（底边）或原始 y 匹配都会系统性错位一个行高。
- **贪心唯一配对**：密集排版页（版本历史/索引）同基线行块被切成多块，按行匹配会把同基线全部行误标为标题（ctex 实测 142 行误报）；每书签只锚最近一行、每行最多一个书签后，ctex 标题 647→228 且正文零误报。
- **结构标签字母聚合**：PdfPig `AddLetter` 只写最内层 BMC，H 标签父元素 Letters 不含后代字母，需递归聚合；Chromium 网页打印的 H 标签是空 BMC 占位（letters=0，正文在兄弟 NonStruct）→ 标签路径对网页打印类天然无效（已知边界）。
- **PdfImageBlock 加 Format**（Jpeg/Png）：`IPdfImage.TryGetPng` 公开可用（0.1.16），Word 导出图片支持面随之变宽（原仅 JPEG）；WriteImage 按 Format 传 NPOI PictureType。
- **fixture 需显式接受 AGPL**：PdfSharp 6.5.0 起 `PdfSharp.PdfSharpLicense.SetAgplLicense()` 不调用则所有 PdfDocument 构造抛 PdfSharpLicenseException（连带恢复了 T042 记录的基线 7 个失败用例，义务口径见 csproj 注释）。
- 页面输入记忆：pdf-management pageId 增 MarkdownOutputPath/ExportMdImages 两键（page-input-archive.md 已同步）。

## 已知边界（v1 口径）
