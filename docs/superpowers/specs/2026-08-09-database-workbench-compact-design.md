# 数据库工作台紧凑化设计规格

**任务：** T125
**日期：** 2026-08-09
**状态：** 待用户确认后实施
**范围：** 现有数据库工作台与“导出文档”对话框的界面信息架构和视觉密度优化

## 1. 背景与目标

当前表详情工作区在左侧“对象浏览器”之外，又展示了一列“数据表列表”。两处都能定位表对象，造成导航职责重复；而详情区被挤压，未选中表时会出现明显的无效留白。

本次调整的目标是形成紧凑、专业的数据库工具工作流：

1. 只保留左侧对象树作为对象导航入口，选中对象后直接在右侧打开详情。
2. 将右侧详情作为主工作区，优先展示字段、索引、DDL 和对象操作。
3. 收紧工具栏、面板留白与导出向导的内容层级，保持桌面端高信息密度和明确的操作主次。
4. 不改变连接、对象加载、选中对象、导出、SQL 查询和代码生成的现有业务行为。

## 2. 范围与非范围

### 本次范围

- 移除 `TableDetailView` 中的“数据表列表”面板及其底部“刷新详情 / 清空”操作区。
- 保留并强化左侧“对象浏览器”作为唯一对象导航区。
- 在表详情中直接铺满右侧主工作区，保留未选择对象时的空状态。
- 优化工作台工具栏和导出文档对话框的间距、分组、层级与文本密度。
- 复用已有动态主题和设计令牌，保证亮色、暗色主题均可用。

### 不在本次范围

- 不修改数据库连接、对象读取、表元数据加载、导出文件生成或 SQL 执行逻辑。
- 不新增表过滤、收藏、分页、拖拽或多标签页等功能。
- 不修改“更多操作”菜单的命令、顺序和权限行为。
- 不全量替换设计系统或重构无关视图。

## 3. 现有链路与边界

`DatabaseWorkbenchPageView` 的左侧 `DatabaseTree` 是当前对象选择的唯一业务入口：选中架构、数据表、视图或存储过程后，分别激活对应详情工作区。`TableDetailView` 内部的 `Tables / SelectedTable` 列表只是第二套呈现入口；删除该面板不会移除左侧树到详情视图的选择链路。

本次仅调整视图布局和表现层。若删除面板后 `TableDetailViewModel` 中存在仅供该列表使用、且没有其他调用方的状态或命令，将在实施阶段通过静态引用检查后再做最小清理；否则不修改 ViewModel。

## 4. 界面结构

### 4.1 数据库工作台

目标布局（建议桌面宽度 1280px 及以上）：

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ DB  数据库工作台  [连接选择] [数据库选择] [管理连接] [更多操作]  ● 当前连接 │
├─────────────────────────────────────────────────────────────────────────────┤
│ 对象浏览器（固定约 300px） │  对象详情（自适应填满剩余空间）                │
│ [搜索对象……]               │  ┌ 表名称 / 架构 / 操作 ───────────────────┐  │
│ 架构                        │  │ 概览 / 字段 / 索引 / DDL               │  │
│  └ public                   │  │                                        │  │
│     └ 表                     │  │ 表结构、字段表格、索引和 DDL            │  │
│        └ vector_collection  │  │                                        │  │
│                              │  └────────────────────────────────────────┘  │
│ [刷新] [清空搜索]           │                                                │
└─────────────────────────────────────────────────────────────────────────────┘
```

明确删除“数据表列表”中间栏。用户从左侧树选择表后，表详情直接占满主工作区；选择架构但未选择表时，在同一主工作区显示简洁的“请选择数据表”引导。

### 4.2 导出文档向导

```text
┌──────────────────────────── 导出文档 ──────────────────────────────────────┐
│ ↗  导出向导：选择对象 → 配置输出                         [连接 / 数据库]  │
├───────────────────────────────┬─────────────────────────────────────────────┤
│ 1  导出对象                   │ 2  输出配置                                │
│ [全选] [清空]                 │ 文档名称 [____________________]            │
│ 连接 / 数据库摘要              │ 输出路径 [________________] [浏览]          │
│ ────────────────────────────  │ 格式： [Excel] [Markdown]                  │
│ 可勾选对象树（可滚动）         │ 简短格式说明                                │
├───────────────────────────────┴─────────────────────────────────────────────┤
│ 已选择 N 个对象                                      [取消] [开始导出]     │
└─────────────────────────────────────────────────────────────────────────────┘
```

保留两步布局和固定底部操作栏。左侧负责选择，右侧只负责文件名、目录和格式；文案缩短为操作说明，避免与控件争夺视觉焦点。格式卡片保持整块可点击，选中态使用现有主强调色，不增加新配色。

## 5. 视觉与响应式规则

1. 使用现有 `Brush.*`、`Space.*`、`Radius.*`、`Shadow.*`、`Font.*` 动态资源；不硬编码新颜色、圆角、阴影或主题相关尺寸。
2. 工作台外层保持 20px 内容边距；对象树宽度约 300px，树与主工作区之间保留一个紧凑分隔间距。删除中间栏后，详情区不得保留占位列或无效分隔带。
3. 主工具栏采用单行、36px 级控件高度；标题只保留“数据库工作台”和一行简短副标题。连接状态靠右，以截断而非换行避免工具栏膨胀。
4. 导出窗口维持当前最小宽度 960px；内容区为约 56% : 44% 的双栏。滚动仅发生在对象树区域，页脚始终可见。
5. 在 960px 以下的可用宽度，工作台按已有桌面最小宽度策略显示，不新增移动端重排规则；导出窗口保持其最小宽度约束。

## 6. 交互与状态

| 场景 | 调整后的表现 | 业务边界 |
| --- | --- | --- |
| 选择架构 | 左侧树展开对应对象；右侧保持表详情工作区的“请选择数据表”状态 | 不改变架构加载逻辑 |
| 选择数据表 | 右侧直接显示表概览、字段、索引与 DDL | 不改变 `SelectedTable` 与详情加载逻辑 |
| 选择视图 / 存储过程 | 右侧切换既有详情视图 | 不修改原有导航映射 |
| 点击“刷新” | 仅刷新左侧对象树 | 不保留已删除中间列表的“刷新详情”入口 |
| 点击“更多操作” | 菜单继续打开，导出、pg_dump、生成代码命令保持可用 | 不改命令及对话框所有权链路 |
| 导出对象为空 | 保留现有空状态、加载失败与重试反馈 | 不修改导出校验和生成逻辑 |

## 7. 实施计划

1. 调整 `TableDetailView.axaml`：删除分栏对象列表，仅保留加载条、空状态与全宽 `TableDetailContent`。
2. 调整 `DatabaseWorkbenchPageView.axaml`：收紧工具栏与对象树表述、间距，保持命令和绑定不变。
3. 调整 `ExportDialog.axaml`：压缩标题、表单和格式卡片间距，保持两栏选择 / 配置与粘性页脚。
4. 通过引用搜索确认是否有只供移除列表使用的 ViewModel 属性或命令；只清理无调用方的代码。
5. 补充或更新受影响的 Avalonia Headless 测试，验证工作台对象树入口、详情呈现，以及“更多操作 → 导出”可挂载。

## 8. 验收与验证

1. 在 1280×800、1440×900、1920×1080 桌面尺寸下，表详情不再出现中间“数据表列表”或空白占位列，右侧详情填满可用区域。
2. 左侧对象树选择表、视图、存储过程后，右侧仍展示相应详情；未选表时显示正确引导。
3. “更多操作”菜单仍能打开，点击“导出文档”仍能显示导出向导。
4. 导出向导中对象树、文件名称、目录选择、Excel / Markdown 选中态和底部导出按钮均可见且不重叠。
5. 运行数据库相关 Headless 测试与 Release 构建；必要时补充人工桌面 smoke test，覆盖亮色和暗色主题。

## 9. 风险与回退

- 风险：表详情 ViewModel 可能仍保留历史列表状态。实施时先确认引用，再决定是否清理，避免误删仍在使用的功能。
- 风险：高密度布局可能使窄窗口文本截断。通过现有最小宽度、文本截断和对象树区域滚动控制风险。
- 回退：本次仅涉及 AXAML 表现层和必要的无引用清理；若出现交互回归，可独立恢复 `TableDetailView` 的分栏布局，不影响数据和导出文件。
