# Word 转 Markdown（REQ-WORD-001）

## 项目背景

开发与写作场景常需要把 Word 文档（接口文档、方案说明）转成 Markdown 用于知识库、README 或大模型输入。在线转换器需要上传文件，存在隐私顾虑；命令行工具（pandoc）对普通用户不友好且需单独安装。工具箱内置该能力，全程本地处理。

## 目标与范围

在应用内提供 Word（.docx）转 Markdown 工作台：载入本地 docx，转换为 Markdown 文本并导出为 .md 文件，内嵌图片可导出到 md 同级的资源目录。

本次范围：

- 载入本地 .docx 文件并展示文件名、大小；
- 转换为 Markdown：标题层级、加粗 / 斜体 / 删除线、上下标、行内代码、有序 / 无序列表、GFM 表格、超链接；
- 图片处理两种模式：导出到 `<md 文件名>.assets/` 目录并以相对路径引用（默认），或忽略图片；
- 转换完成后在页面内预览 Markdown 源文本；
- 全程本机完成，不上传任何网络服务。

不在本次范围：

- 旧版二进制 .doc（97-2003）输入；
- Markdown 反向转 Word；
- 公式（OMML）、文本框、SmartArt 等复杂对象的完整还原（尽力而为）；
- 批量多文件处理。

## 用户角色

- 开发人员：把接口文档、设计说明转为 Markdown 归档到知识库。
- 一般办公用户：把现有 Word 内容转为 Markdown 用于发布或协作。

## 页面清单

- Word 转 Markdown 工作台（主窗口内单个模块页，含文件载入、输出配置与转换预览）。

## 核心业务流程

1. 用户选择本地 .docx 文件，页面展示文件名与大小。
2. 用户确认输出 .md 路径与图片处理方式（默认：导出图片到同名 .assets 目录）。
3. 用户执行「开始转换」，完成后展示成功反馈、输出路径、标题数与图片数，并在预览区显示 Markdown 源文本。
4. 失败时展示可读原因，不产生输出文件。

## 关键业务对象及字段含义

- 源文件：本地 .docx 路径与大小；
- 输出目标：.md 输出路径，默认取源文件同名 .md；
- 图片模式：导出（图片落盘 `<md 名>.assets/`，md 内写相对引用）或忽略（图片整体丢弃，md 内不出现图片引用）；
- 转换结果：输出路径、导出图片数、识别标题数、Markdown 源文本（预览用）。

## 权限与可见范围

本机单用户使用，不引入权限控制；仅读写用户指定的本地文件与输出目录。

## 边界场景与异常

- 源文件不存在、扩展名不是 .docx 时，给出具体原因且不进入转换；
- 输出路径为空时提示，不进入转换；
- 源文件损坏或非合法 zip 包（docx 本质为 OPC 包）导致解析失败时，展示失败原因；
- 转换成功但文档含公式 / 文本框等无 Markdown 对应物的元素时按尽力而为降级，不视为失败。

## 非功能要求

- 本地处理，文件不上传；
- 转换内核基于 DocSharp.Docx（MIT，NuGet），不引入外部进程（pandoc）或商业授权组件；
- 大文件转换期间给出进行中反馈，不阻塞界面。

## 验收标准

1. 中文版 Word 生成的 docx（标题样式 styleId 为数字本地化 ID）能正确转换出 `#` ~ `######` 标题层级。
2. 加粗、斜体、删除线、行内代码、超链接、GFM 表格在输出中语义正确。
3. 默认模式下内嵌图片导出到 `<md 名>.assets/` 目录，md 内为相对路径引用，md 移动时连同 assets 目录一起移动不断链；忽略模式下 md 内无图片引用且不产生 assets 目录。
4. 页面可预览转换后的 Markdown 源文本。
5. 失败场景（文件不存在、非 docx、损坏文件）均给出明确原因，不产生输出文件。
6. 全程无网络上传行为。

## 待确认项

1. 复杂排版（嵌套列表层级、Intense Quote 等字符样式下划线）的还原精度以 DocSharp 输出为准，已知噪声（目录书签锚点、下划线 HTML 标签）在本期做锚点清洗，其余保留。
2. 是否需要后续支持 .doc（97-2003）输入（需引入 DocSharp.Binary.Doc 二进制转换包，另行评估）。
