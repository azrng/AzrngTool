# 编码 / 解码工具组（REQ-ENCODE-001）

> 本文档为依据当前实现整理的回溯基线，待用户确认后转为 approved。

## 项目背景

开发过程中频繁处理各类编码转换：Base64、URL、Unicode、十六进制、Gzip、JWT 内容查看、繁简体中文转换等。这类转换是一次性、碎片化的，使用在线工具需要粘贴内容且可能包含敏感信息，本地工具箱可以即时完成且不出本机。

## 目标与范围

提供九个独立工具页，覆盖常见编码转换场景，全部为本地即时转换。

本次范围（导航分组"编码/解码类工具"）：

| 工具页 | 职责 |
| --- | --- |
| BASE64 文本 | 文本与 Base64 双向转换 |
| Base64 转图片 | Base64 数据与图片双向转换，支持预览 |
| URL 编码解码 | URL 百分号编码与解码 |
| Unicode 编码解码 | 文本与 Unicode 转义序列双向转换 |
| 十六进制转换 | 文本与十六进制表示双向转换 |
| 繁简体转换 | 繁体中文与简体中文互转 |
| JWT 解码器 | 解析 JWT 并展示内容 |
| Gzip 编码解码 | 文本与 Gzip 压缩数据双向转换 |
| 编码解码 | 组合工作台，多种编码在同一页面组合使用 |

不在本次范围（如需再做评估）：

- JWT 签名验证（当前为解码器定位）；
- 图片格式批量转换。

## 用户角色

- 开发人员：排查编码问题、解读 JWT / Base64 内容、构造测试数据。

## 页面清单

上表九个工具页，每页为独立模块页。

## 核心业务流程

每个工具页为统一的单页流程：

1. 输入源内容；
2. 选择转换方向（编码 / 解码）或选项；
3. 页面即时转换并展示结果；
4. 复制结果使用；非法输入给出可读提示。

## 关键业务对象及字段含义

- 各工具页的输入输出均为文本（Base64 转图片额外涉及图片预览与保存）；
- JWT 解码器输出为分段解析后的头与负载内容；
- 组合工作台支持在同一页面串联使用多种编码转换。

## 权限与可见范围

本机单用户使用，无权限控制，无网络请求。

## 边界场景与异常

- 非法 Base64、十六进制、Gzip 数据或损坏的 JWT，给出可读提示且不输出错误结果；
- Base64 转图片遇到不支持的图片数据时提示原因；
- 空输入提示补全。

## 非功能要求

- 本地即时转换，无网络请求，无持久化；
- 各工具页互不影响。

## 验收标准

1. 各编码页在编码 / 解码两个方向上对合法输入结果正确（可往返还原）。
2. 非法输入有可读提示，不产生错误结果。
3. 结果可一键复制；Base64 转图片支持预览。

## 待确认项

1. JWT 解码器是否需要在后续版本补充验签能力。
2. Base64 转图片支持的图片格式范围，需核对实现后补充。
3. 繁简转换的词库覆盖范围（单字 / 常用词）。
