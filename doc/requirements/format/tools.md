# 格式化工具组（REQ-FORMAT-001）

> 本文档为依据当前实现整理的回溯基线，待用户确认后转为 approved。

## 项目背景

开发过程中频繁需要格式化与转换文本：JSON 美化与压缩、SQL 整理、JSON / YAML / XML 之间互转、正则验证、字数统计、金额大写等。这类操作碎片化且可能包含业务数据，使用在线工具不便且有泄露风险。工具箱将其收拢为本地格式化工具组。

## 目标与范围

提供九个独立工具页，覆盖文本与结构化数据的格式化、转换、校验场景，全部为本地即时处理。

本次范围（导航分组"格式化类工具"）：

| 工具页 | 职责 |
| --- | --- |
| 文本压缩 | 压缩文本（去除多余空白） |
| JSON 格式化 | JSON 缩进美化与压缩 |
| SQL 操作 | SQL 语句格式化整理 |
| XML 转 HTML | 基于 XSLT 将 XML 转换为 HTML |
| JSON/YAML/XML 互转 | 三种格式两两互转，附格式化与语法校验 |
| 正则表达式测试 | 正则编辑与匹配测试 |
| 字数统计 | 文本字数与统计信息 |
| 人民币大写转换 | 数字金额转人民币大写 |
| MIME 类型查询 | 按扩展名 / 类型查询 MIME |

不在本次范围（如需再做评估）：

- JSON Path / XPath 提取器；
- SQL 美化之外的分析能力（格式化依赖项、语法树展示等）。

## 用户角色

- 开发人员：格式化接口报文、整理 SQL、验证正则、转换配置格式。
- 一般用户：字数统计、金额大写等日常文本处理。

## 页面清单

上表九个工具页，每页为独立模块页。

## 核心业务流程

1. 输入源内容，选择目标格式或操作；
2. 执行转换 / 格式化 / 校验；
3. 结果区展示输出内容与校验信息（成功或失败原因）；
4. 复制结果使用；非法输入给出可读错误。

JSON/YAML/XML 互转补充规则：

- 源格式与目标格式相同时提示无需转换，可改用"格式化"；
- 转换与校验失败时提示具体原因（含行号信息），不输出错误结果。

## 关键业务对象及字段含义

- 各工具页输入输出以文本为主；
- JSON/YAML/XML 互转：源格式、目标格式（JSON / YAML / XML 三选）、源文本、目标文本、校验信息；
- XML 与结构化数据互转遵循常见约定：属性映射为 `@名称` 键，元素文本映射为 `#text` 键。

## 权限与可见范围

本机单用户使用，无权限控制，无网络请求，无持久化。

## 边界场景与异常

- JSON / YAML / XML 解析失败时给出含行号的可读原因，不输出半成品结果；
- 空输入提示补全，不执行操作；
- XML 转 HTML 依赖 XSLT 运行时能力，在 AOT 发布版本中不可用，页面需明确提示该限制；
- 正则表达式非法时提示错误位置。

## 非功能要求

- 本地即时处理，无网络请求；
- 常规规模输入下无明显等待；
- 工具页不持久化用户输入。

## 验收标准

1. JSON 格式化、SQL 操作、文本压缩对合法输入输出正确结果。
2. JSON / YAML / XML 三格式两两互转结果正确，往返转换不丢失结构信息（遵循属性与文本约定）。
3. 校验功能能区分语法通过与否，失败时给出含行号的原因。
4. 所有输出可一键复制。

## 待确认项

1. 正则表达式测试页与 SQL 语句分析能力的联动范围，需核对实现后补充。
2. JSON/YAML/XML 互转对特殊 XML 结构（多根节点、注释、指令）的处理边界。
