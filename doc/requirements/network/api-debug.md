# 接口调试（REQ-NETWORK-001）

> 本文档为依据当前实现整理的回溯基线，待用户确认后转为 approved。

## 项目背景

开发与联调过程中需要频繁向 HTTP 接口发送请求验证行为。浏览器地址栏只能发 GET、命令行工具不易维护请求头与请求体，外部调试工具则需要额外安装。工具箱内置接口调试工作台，可以在开发环境中就地完成请求配置、发送与结果查看，并保留最近请求便于回放。

## 目标与范围

在应用内提供单页接口调试工作台：配置并发送 HTTP 请求，查看响应结果，管理本地请求历史。

本次范围：

- 请求配置：请求方法、URL（含参数编辑）、请求头、请求体；
- 发送与取消：请求执行期间展示进行中状态，并支持取消；
- 响应展示：状态码、耗时与响应内容；
- 完整请求 URL 回显，便于确认最终请求地址；
- 本地请求历史：以抽屉侧栏呈现，支持回填复用，条目数量有上限。

不在本次范围（如需再做评估）：

- 环境变量与多环境切换；
- 请求脚本、断言与批量执行；
- Mock 服务、接口集合管理与团队共享。

## 用户角色

- 开发人员：联调自研服务或第三方接口，验证参数与响应。
- 测试人员：对接口做快速手工验证。

## 页面清单

- 接口调试页（主窗口内单个模块页，含请求编辑区、响应区与历史抽屉侧栏）。

## 核心业务流程

1. 用户选择请求方法并填写 URL，按需编辑参数、请求头与请求体。
2. 点击发送后进入请求中状态，页面展示进行中反馈，用户可取消本次请求。
3. 请求结束后展示状态码、耗时与响应内容；失败时展示可读错误原因。
4. 已完成的请求记入本地历史；用户从历史选择条目可回填表单再次发送。

## 关键业务对象及字段含义

- 请求快照：方法、URL、参数、请求头、请求体，描述一次可重放的请求配置；
- 执行结果：状态码、耗时、响应内容、错误信息；
- 历史条目：请求快照加执行时间，按时间倒序排列，数量有上限（当前实现 50 条）。

## 权限与可见范围

本机单用户使用，不引入权限控制；历史数据仅存本机用户目录，不上传网络服务。请求可达性取决于目标服务与所在网络环境。

## 边界场景与异常

- URL 为空或格式非法时，给出可读提示，不发起请求；
- 网络不可达、连接超时、目标服务报错时，明确区分错误类型并展示原因；
- 请求执行期间用户取消后，回到可编辑状态，不残留半成品结果；
- 非 2xx 响应属于正常展示范畴，按响应内容呈现，不作为异常弹窗打断；
- 历史超过上限时淘汰最旧条目。

## 非功能要求

- 请求执行不阻塞界面，等待期间其他页面可正常使用；
- 历史数据仅落本机；
- 页面布局在窄窗口下保持请求编辑区可用。

## 验收标准

1. 配置方法、URL、参数、请求头与请求体后发送，响应区正确展示状态码、耗时与响应内容。
2. 完整 URL 回显与实际请求地址一致（含拼接的查询参数）。
3. 请求执行期间可取消，取消后可立即再次发起请求。
4. 历史条目按时间倒序展示，选择历史可回填表单重发；条目数不超过上限。

## 待确认项

1. 请求体支持的格式清单（如 form、raw text、JSON 等）以页面当前实现为准，是否满足现有使用。
2. 是否需要在后续版本引入环境变量与多环境切换。
3. 历史条目保存的字段范围（是否包含响应摘要）。
