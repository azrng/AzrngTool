## 技术设计

### 模块职责

| 模块 | 职责 | 复用现有能力 |
| --- | --- | --- |
| `ClipboardMonitorService`（Singleton） | 轮询检测剪贴板变化，读取并归类内容，调用存储服务入库；提供暂停开关与变更事件 | 约定注入 `ISingletonDependency`；单例事件模式参考现有服务 |
| `ClipboardStoreService`（Singleton） | 内存持有全部条目，防抖落盘 `history.json`，管理 `images\` 缓存与淘汰 | 复用 `ToolUsageStatsService` 的防抖落盘模式 |
| `ClipboardHistoryViewModel`（页面级） | 搜索、过滤、固定、删除、复制回剪贴板等命令与列表状态 | `ViewModelBase`、`CommunityToolkit.Mvvm`、现有列表页模式 |
| `ClipboardHistoryView` + `Controls` | 页面布局、虚拟化列表、图片缩略图、大图查看浮层 | `ViewLocator` 约定、设计 token（`StaticResource` 间距 / `DynamicResource` 主题色） |
| 主窗口导航 | 新增"剪贴板历史"菜单入口 | `MainWindowViewModel` 菜单构建与 `GetMenuKey` 约定 |

### 数据流向

```text
系统剪贴板（任意应用复制）
        ↓ 1s 轮询 GetClipboardSequenceNumber（UI 线程 DispatcherTimer）
ClipboardMonitorService
  ├── 读取并归类：Files > Image > Text
  ├── 暂停开关开启 → 丢弃
  └── 未暂停 → 交存储服务
ClipboardStoreService（内存为权威副本）
  ├── 去重：命中 → 更新 LastCopiedUtc / 置顶
  ├── 入库：新增条目；图片即时写 images\<id>.png
  ├── 淘汰：数量 / 期限 / 图片容量上限
  ├── 防抖 2s 写 history.json
  └── 触发 Changed 事件
        ↓
ClipboardHistoryViewModel（页面打开时订阅）
  └── 过滤 / 搜索 → ObservableCollection → 虚拟化列表
```

关键点：存储服务在应用启动即构造并全量加载 `history.json`（几百条毫秒级），采集不依赖页面是否打开；页面 ViewModel 只读内存快照并订阅事件，不直接读写文件。

### 状态变化

- 监听器：`Running` ⇄ `Paused`（用户开关）；单次检测内部为 `Detect → Read → Classify → (Store | Skip)`，任何一步失败回到 `Running` 继续下一轮。
- 条目生命周期：`新建（Unpinned）→ 复制命中去重（更新 LastCopiedUtc）→ 固定（Pinned）/ 删除 / 过期淘汰`。
- 页面：`Loading（存储初始加载）→ Ready ⇄ Filtered（搜索 / 过滤生效）`；存储读失败时进入 `Error` 并提供重建入口。
- 列表条目可见状态：正常 / 图片缓存丢失占位 / 已选中。

### 技术决策与依赖边界

1. **变化检测用序列号轮询而非消息钩子**：Win32 `GetClipboardSequenceNumber()` 是无副作用的单次调用（不打开剪贴板、不占用），1 秒间隔开销可忽略；避免为监听单独维护消息窗口和消息过滤器。监听器收敛在 `IClipboardMonitor` 抽象后，后续若需要零延迟再替换为 `AddClipboardFormatListener`，ViewModel 与存储层不动。
2. **读取走 Avalonia `IClipboard`**：`GetFilesAsync` / 数据格式探测 / `GetTextAsync` / `GetImageAsync`，在 UI 线程 DispatcherTimer 上执行，避免跨线程访问剪贴板。首版只识别 `FileNameW`（文件列表）、位图格式、`UnicodeText`；HTML / RTF 等格式直接跳过。
3. **存储用 JSON 文件而非 SQLite**：条目硬上限 500、单文本 32KB，全量常驻内存毫秒级可承受；沿用仓库既有 `LocalAppData` JSON + 防抖落盘模式，不新增数据库依赖。若未来放开条目上限或需要全文索引，再评估 SQLite（淘汰逻辑与契约不变，只替换存储服务实现）。
4. **图片双写时机**：PNG 文件在入库时同步写盘（几 MB 内可接受），`history.json` 防抖 2 秒合并写；先写图片后更新元数据，崩溃时最多产生孤儿图片，由启动时清理兜底。
5. **去重规则**：按契约去重键精确匹配；命中已固定条目时仅更新 `LastCopiedUtc`，不改变固定状态。
6. **缩略图**：列表项直接从 `images\` 文件按需解码（`Bitmap` + 虚拟化按可见项加载），ViewModel 层维护小容量 LRU 位图缓存，不另存缩略图文件。

## 交互与异常

### 核心操作流程

1. **采集**：用户在任意应用复制 → 监听器检测到序列号变化 → 归类入库 → 页面打开时列表置顶刷新并短暂高亮新条目；页面未打开时仅入库。
2. **复制回剪贴板**：双击条目或点击"复制" → 内容写回系统剪贴板（文本 `SetTextAsync`、图片写位图、文件写文件列表）→ toast「已复制」→ 更新 `LastCopiedUtc` 并置顶。被截断的文本复制回截断内容，toast 附注「原内容过长，已复制截断部分」。
3. **固定 / 取消固定**：星标切换；固定条目移入固定区，取消固定回到"全部历史"按时间排序。
4. **删除**：单条删除无需确认（可重新复制，成本低）；"清空未固定"弹确认对话框，执行后仅清未固定条目。
5. **文件条目"打开"**：资源管理器定位首个文件；路径已失效时 toast 提示，条目保留。
6. **图片查看**：点击缩略图打开大图浮层（ESC / 点击遮罩关闭）。
7. **暂停采集**：头部开关切换，暂停期间复制不入库；开关状态记忆在会话内，不持久化（重启默认恢复采集）。

### 边界与失败边界

| 场景 | 处理 | 级别 |
| --- | --- | --- |
| 剪贴板被占用 / 读取间隙内容变化 | 跳过本次，下一轮继续 | warning 日志，不打扰用户 |
| 文本 > 256KB | 不入库，toast 一次性提示 | warning |
| 32KB–256KB 文本 | 截断 32KB 存储，条目标记"已截断" | 静默 |
| 图片写盘失败 | 该条不入库 | warning 日志 |
| `history.json` 损坏 | 改名 `.bak` 后从空重建，页面进入错误态提供"重新加载" | fail-soft，不阻塞启动 |
| `images\` 文件丢失 | 条目显示占位，操作区保留删除 | 静默 |
| 孤儿图片（元数据已无对应条目） | 启动时清理 | 静默 |
| 存储写盘失败 | 保留内存权威副本，下轮防抖重试 | warning |

原则：采集与存储层全部 fail-soft，任何单次失败不允许影响监听循环与应用启动；只有复制回剪贴板这类用户显式发起的操作失败才以 toast 显式报错。

### 副作用清单

- 写 `%LocalAppData%\AzrngTools\clipboard\history.json`（防抖）与 `images\<id>.png`（入库时）；
- 写回系统剪贴板（用户显式操作触发）；
- 无网络请求、无注册表、无开机自启项。

### 验证方式

- 单元测试（`AzrngTools.Tests`）：存储服务往返序列化、去重、数量 / 期限 / 图片容量淘汰、截断阈值、损坏文件重建、孤儿图片清理；
- ViewModel 测试：搜索过滤、类型切换、固定 / 取消固定、删除与清空的状态变化；
- 手动 smoke（Windows）：文本 / 图片 / 文件三类复制采集与复制回放、暂停开关、大文本与超大文本路径；
- 回归点：不打开剪贴板页时其他工具功能不受监听影响，应用启动耗时无可感知退化。

## 设计自检

- **入口**：系统剪贴板变化（自动）；主窗口导航"剪贴板历史"（页面）。
- **核心流程**：检测 → 归类 → 入库 → 防抖落盘 → 页面过滤展示 → 复制回放，见数据流向。
- **状态变化**：监听 Running/Paused、条目 Unpinned/Pinned/Deleted、页面 Loading/Ready/Filtered/Error，见"状态变化"。
- **关键分支**：正常路径全链路；异常路径见失败边界表；缺数据路径（图片丢失、文件失效、空历史）均有对应展示。
- **副作用**：仅本机文件写入与显式剪贴板写回，见副作用清单。
- **失败边界**：采集与存储 fail-soft；用户显式操作失败显式报错；数据损坏备份重建，见失败边界表。
