# 编码 / 解码工具组设计（DES-ENCODE-001）

> 本文档为依据当前实现整理的回溯基线，待用户确认后转为 approved。

## 需求追溯

- 关联需求：`REQ-ENCODE-001`。
- 覆盖导航分组"编码/解码类工具"下九个工具页的实现模式与关键决策。

## 技术设计

### 共性实现模式

九个工具页与生成类工具组同构，遵循同一页面模式：

| 层 | 约定 |
| --- | --- |
| ViewModel | 每页一个 `XxxEncodePageViewModel`（`ViewModelBase` + CommunityToolkit.Mvvm） |
| 视图 | `Views/Encode/`，经 `ViewLocator` 命名约定绑定 |
| 持久化 | 无；无网络请求 |

页面结构统一为：输入区 → 方向 / 选项 → 输出区 → 复制。JWT 解码器与组合工作台在此模式上做变体。

### 各页要点

| 页面 | 要点 |
| --- | --- |
| BASE64 文本 | 文本与 Base64 双向转换 |
| Base64 转图片 | Base64 数据解码为图片预览，图片编码为 Base64 |
| URL / Unicode / 十六进制 | 双向转换，处理字符集转义 |
| 繁简体转换 | 繁简互转 |
| JWT 解码器 | 按 `.` 分段解析 JWT，解码展示头与负载内容；定位为解码器，不含验签（见需求待确认项） |
| Gzip 编码解码 | 文本与 Gzip 压缩数据双向转换 |
| 编码解码（组合工作台） | 同一页面组合使用多种编码转换 |

### 关键技术决策

1. **不建服务层**：转换均为无状态即时计算，与生成类工具组保持一致的模式；编码实现优先复用 .NET 基类库与 `Azrng.Core`。
2. **失败短路**：非法 Base64 / 十六进制 / Gzip / JWT 输入直接提示原因，不输出错误结果，避免用户把解码失败的乱码当有效数据使用。
3. **JWT 只解码不验签**：与页面定位（"JWT 解码器"）一致；验签能力如需补充，另行进入需求与设计流程。

## 交互与异常

| 场景 | 处理 |
| --- | --- |
| 输入为空 | 提示补全 |
| 非法编码数据 | 提示可读原因，不输出结果 |
| 不支持的图片数据 | 提示原因 |
| 转换成功 | 输出区更新，支持一键复制 |

## 验证方式

- 手动 smoke：各页编码 / 解码往返（编码后再解码应还原原文）；非法输入报错路径；Base64 图片预览；JWT 解码样例。
