# Azrng.DataAccess 连接安全改进建议

## 背景
- 数据库模块审查发现 `DatabaseService.BuildConnectionString` 会将密码拼入完整连接字符串。
- 当前仓库已经避免将明文连接字符串落盘，但运行时仍需要向部分 `Azrng.DataAccess` 桥接器或底层 ADO.NET 连接传递完整连接字符串。

## 当前限制
- `PostgreBasicDbBridge`、`SqliteBasicDbBridge` 当前调用路径使用完整连接字符串构造。
- `DataSourceConfig` 已能承载 `Host`、`Port`、`DbName`、`User`、`Password`，但不同数据库桥接器对 `DataSourceConfig` 和连接字符串构造方式不统一。
- 在当前应用层单独修改无法消除运行时连接字符串中的密码，只能减少落盘、日志和异常输出中的暴露面。

## 建议在 Azrng.DataAccess 包内处理
- 为所有 `IBasicDbBridge` 和 `IDbHelper` 提供统一的 `DataSourceConfig` 构造入口，应用层只传配置对象，不自行拼接连接字符串。
- 在包内使用各数据库官方连接字符串 builder 或连接对象参数化能力生成连接，避免应用层散落字符串模板。
- 对日志、异常、诊断输出统一做敏感字段脱敏，至少覆盖 `Password`、`PWD`、`User Id`、`Username` 等键。
- 如必须暴露连接字符串，提供包内 `MaskConnectionString` 或等价工具，禁止调用方自行处理。
- 针对 PostgreSQL、SQLite、SQL Server Windows 身份认证等现有特殊路径补齐测试，确保迁移后连接行为一致。

## 当前仓库临时边界
- 本仓库继续保留现有运行时连接字符串构造，以避免破坏当前 `Azrng.DataAccess` 构造契约。
- 本仓库后续只应在日志、错误提示、导出配置和文档中避免输出明文密码。
