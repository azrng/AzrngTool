# 项目需求说明

## 项目背景

AzrngTool 的数据库工作台集中提供数据库连接、对象浏览、对象详情、SQL 查询、文档导出、pg_dump 导出和代码生成能力。现有页面将这些能力分布在顶部工具栏、左侧对象浏览器、首屏概览和各工作区中，同一连接上下文多次呈现，导致主要操作路径不够聚焦。

## 目标与范围

本次仅重设计“数据库工作台”的桌面端界面与交互组织方式，使用户能更快完成“选连接 → 浏览对象或执行 SQL → 查看 / 导出结果”的日常路径。

范围包括：

- 数据库工作台主页面的布局、信息层级、导航和状态反馈；
- SQL 查询工作区的工具栏、编辑器和结果区的布局与文案；
- 表、视图、存储过程详情页与主工作区的视觉一致性；
- 窄窗口下的面板收起与恢复策略。

不在本次范围：

- 修改数据库连接、查询执行、对象加载、导出或代码生成的业务规则；
- 变更数据模型、持久化格式、权限模型或数据库支持范围；
- 新增 SQL 智能补全、事务管理、多标签查询等未实现能力。

## 用户角色

- 开发人员：频繁连接测试库，浏览表结构，编写并执行 SQL。
- 数据库维护人员：检查对象定义，执行受控查询，导出文档或备份。

## 页面或模块清单

- 数据库工作台主页面；
- 对象浏览器；
- 欢迎 / 未选择对象状态；
- 表、视图、存储过程详情工作区；
- SQL 查询工作区；
- 连接管理与导出入口（沿用现有抽屉 / 对话框能力）。

## 核心业务流程

1. 用户在统一上下文栏选择或管理连接，并选择数据库。
2. 用户在对象浏览器按对象类型浏览或搜索，选择对象后在主工作区查看详情。
3. 用户可随时切换到 SQL 查询，在当前连接与架构上下文中执行语句并查看结果。
4. 用户从“更多操作”打开文档导出、pg_dump 导出或代码生成，原有危险 SQL 二次确认继续生效。

## 关键数据与字段

- 当前连接：名称、类型、服务器 / 数据库标识、连接状态；
- 当前数据库与架构；
- 对象树：对象类型、名称、搜索关键字、加载状态；
- SQL：编辑内容、模板、最近历史、执行状态、影响行数、结果集与错误信息；
- 对象详情：表 / 视图 / 存储过程的名称、备注、结构与定义。

## 权限与可见范围

沿用当前数据库连接能力及对象访问结果。本次不引入额外权限控制；没有对象访问权限时，页面应明确展示无权限状态，不得伪装为空结果。

## 边界场景与异常

- 未选择连接时，主工作区引导用户选择或创建连接；
- 未选择数据库时，仅展示连接上下文和下一步提示；
- 对象加载、查询执行、导出处理中提供局部加载反馈，避免锁住整页；
- 对象为空、查询无结果、加载失败和无权限均展示可理解的原因及下一步操作；
- 低于 960px 宽度时，对象浏览器应可收起为抽屉，不能挤压主工作区。

## 非功能要求

- 遵循现有 Avalonia Fluent Design 和 `design-system.yaml` 的语义化资源；
- 保持键盘可达、可见焦点和状态文字，不以颜色作为唯一信息来源；
- 在 1280、1440、1920 宽度及紧凑宽度下验证主要布局；
- 界面重设计不得改变已有命令、数据加载时序和危险操作确认机制。

## 待确认项

- SQL 历史是否需要跨会话持久化；当前实现仅保留当前会话内最近 15 条。
- 是否需要在后续迭代引入查询多标签、收藏 SQL 或对象固定功能；这些能力不纳入本次实现。
