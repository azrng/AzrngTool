# 2026-06-04 14:10 适配 Azrng.Core ResultModel 新 API

## 背景

Azrng.Core 升级到 1.18.0，新增了 `ResultModelFactory`、`ResultModelExtensions`、`ResultModelExceptionExtensions` 通用能力；Azrng.DataAccess 升级到 1.0.0-beta4，新增了 `DataSourceConnectionStringBuilder`。当前仓库需要适配新 API，替换本地临时 helper。

## 变更

### 删除文件
- `AzrngTools/Services/Database/DatabaseResultModel.cs` — 本地 ResultModel 创建 helper，已由 `ResultModelFactory` 替代
- `AzrngTools/Services/Database/DatabaseResultModelExtensions.cs` — 本地 `DataOrEmpty()` 扩展，已由 `Azrng.Core.Results.ResultModelExtensions` 替代

### 替换逻辑
- `DatabaseResultModel.Success(data, msg)` → `ResultModelFactory.Success(data, msg)`
- `DatabaseResultModel.Failure<T>(msg)` → `ResultModelFactory.Failure<T>(msg, "DATABASE_ERROR")`
- `DatabaseResultModel.Failure<T>(ex, msg)` → `ex.ToFailureResult<T>(msg)`
- `ResultModel<T>.Failure(msg, code)` + 手动 BaseException.ErrorCode 提取 → `ResultModelFactory.FromException<T>(ex, msg)`
- `DataOrEmpty()` 调用方新增 `using Azrng.Core.Results;` 以引用包内扩展

### PdfResultModel 简化
- `PdfResultModel.Success` 内部改为直接调用 `ResultModelFactory.Success`，移除 `ResultModel<T>.Success(data)` + cast 写 Message 的 hack

### 受影响文件（using 补充）
- `DatabaseContextCoordinator.cs`
- `DatabaseExportPayloadService.cs`
- `CodeGenerationPayloadService.cs`
- `DatabaseBrowserViewModel.cs`
- `ExportDialogViewModel.cs`
- `ConnectionDialogViewModel.cs`

- `TableDetailViewModel.cs`
- `ViewDetailViewModel.cs`

### 附带修复
- `PdfManagementPageViewModelTests.cs` 移除引用不存在的 `LicenseStatusText` 属性断言（PDF 功能 T123 遗留问题）

## 验证
- Debug 编译 0 警告 0 错误

## 风险
- 低风险：纯 API 替换，行为等价
- `ToFailureResult` 默认错误码行为与原 `DATABASE_ERROR` 一致（`BaseException` 用其 ErrorCode，其他用默认值）
