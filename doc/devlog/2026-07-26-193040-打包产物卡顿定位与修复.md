# 本次目标
- 定位打包后应用"用起来卡卡的"（尤其切换界面时卡顿）的根因
- 在最小扰动前提下修复页面切换卡顿，并优化发布配置

# 根因分析
- 页面切换卡顿：每次导航都会通过 DI 新建一个瞬态页面 ViewModel（数据库工作台一次要重建十余个服务与 5 个子 ViewModel），`ViewLocator` 同时重建整棵 View 控件树，外层 `TransitioningContentControl` 还会在新旧页面交叠期间做双份渲染
- 启动慢、内存高：Release 发布启用 `EnableCompressionInSingleFile=true`，每次启动需要全量解压程序集且无法使用文件映射共享内存页
- 实测数据（同一台 Win10 机器，窗口出现耗时 / 稳定后 WorkingSet）：
  - 单文件 + 压缩（原配置）：4.8s / 380MB
  - 单文件无压缩：1.19s / 201MB
  - 非单文件目录发布：2.36s / 190MB

# 核心改动
- `MainWindowViewModel` 新增 `_pageCache`：同一工具页复用同一 ViewModel 实例，避免每次切换重建页面对象图
- `ViewLocator` 新增 `ConditionalWeakTable` 视图缓存：同一 ViewModel 实例复用同一 View 实例，ViewModel 回收时 View 一并释放
- `MainWindow.axaml` 将 `TransitioningContentControl` 换为 `ContentControl`：去掉过渡动画开销，同时避免复用 View 在动画交叠期间产生父子冲突
- `AzrngTools.csproj` 关闭 `EnableCompressionInSingleFile`（经用户确认）：启动快约 4 倍、内存减半；本地 exe 由 137MB 增至 338MB，发布 zip 经外层压缩后下载体积基本不变
- `publish.ps1` 增加 `--ignore-failed-sources`：私有 NuGet 源 403 时仍可用本地缓存完成发布

# 风险或遗留项
- 页面 ViewModel 常驻缓存后，工具页输入状态会跨切换保留（多数场景是体验改善）；已访问页面会占用少量常驻内存，当前工具数量级下可接受
- 去掉了页面切换过渡动画，若后续想恢复动画需先解决复用 View 与 `TransitioningContentControl` 交叠期的父子冲突
- 本地 exe 体积增大约 200MB，介意磁盘占用时可回退 csproj 中该开关
