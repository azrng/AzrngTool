## 背景
对数据库模块（`Services/Database/`、`ViewModels/Database/`、`Models/Database/`、`Utils/Database/`）做新一轮审查，发现 `2026-06-02-database-module-review.md` 之外未覆盖的若干真实问题，集中在连接缓存、密码安全、SQL 拼接和 DI 边界。用户确认全部修复（P0+P1+P2），并对 SQL 工作台 DROP/TRUNCATE/DELETE 加二次确认；明确不考虑历史连接配置文件兼容。

## 本次改动

### P0-#1 桥接器缓存命中条件失效修复
- `DatabaseService.GetOrCreateDbBridge` 原用 `ReferenceEquals(_cachedConfig, config)` 判断缓存命中，但 `DatabaseConnectionContextService.CreateRuntimeConnection` 每次都 `new` 新副本作为 `ActiveConnectionContext`，导致缓存永不命中、每次都新建桥接器。
- 改为按连接标识（Type+Host+Port+Database+Username+Password+UseWindowsAuthentication）生成 key 比较，`BuildConnectionKey` 设为 `internal static` 便于单测。

### P0-#2 SQL 工作台危险语句二次确认
- `SqlQueryViewModel` 新增 `TryDescribeDangerousStatement`（按分号拆句、首关键字识别 DROP/TRUNCATE/DELETE）和 `ConfirmDangerousSqlAsync` 回调。
- `MainWindowViewModel` 注入 `ConfirmDangerousSqlExecutionAsync`，用 Ursa MessageBox 做二次确认；ViewModel 不直接依赖 Window。

### P1-#3 连接密码改用 Windows DPAPI
- `EncryptHelper` 由硬编码 AES 密钥/IV 改为 P/Invoke `CryptProtectData`/`CryptUnprotectData`（当前用户作用域 + 应用级熵盐）。
- 密钥不再硬编码在程序集内，反编译无法解密；旧 AES 密文/跨用户密文解密失败返回空字符串（按用户确认不考虑历史兼容）。

### P1-#4 移除 ViewModel 的 new DatabaseService() 无参后备构造
- 删除 `SqlQueryViewModel`、`TableDetailViewModel`、`ViewDetailViewModel`、`StoredProcedureDetailViewModel`、`DatabaseBrowserViewModel`、`ExportDialogViewModel`(4参) 的无参/降级构造，强制走 DI 注入共享单例。
- 保留 `ConnectionDialogViewModel`、`MainWindowViewModel`(DB)、`ExportDialogViewModel`(设计时) 的无参构造用于单元测试/设计时，但内部复用 `static readonly SharedDatabaseService`，消除独立桥接器实例。

### P2-#5 连接字符串改用驱动 ConnectionStringBuilder
- `DatabaseService.BuildConnectionString` 由字符串插值改为各官方 `ConnectionStringBuilder`（SqlClient/MySqlConnector/Npgsql/Oracle.ManagedDataAccess.Client/Microsoft.Data.Sqlite），避免 Host/用户名含 `;` 等特殊字符破坏连接串。

### P2-#6 收紧 MySQL ALTER TABLE 拼接
- `BuildMySqlModifyColumnCommentSql` / `AppendMySqlCharacterSetClause` 对 `ColumnType`、`CharacterSetName`、`CollationName` 增加白名单校验；非法值跳过对应子句并记日志，避免元数据异常值被拼入 SQL。

### P2-#7 清理死代码
- 删除 `ConnectionConfig.ToConnectionString`（无调用方，且为字符串拼接版，与 builder 化逻辑重复）。

## 风险与说明
- **DPAPI 不可逆兼容旧配置**：用户已确认不考虑历史兼容，旧连接配置文件中的 AES 密文将无法解密，需重新输入密码。
- **DPAPI 绑定当前 Windows 用户**：连接配置文件跨用户/跨机器迁移时密码需重新输入，这是 DPAPI 的安全特性。
- **SQL 二次确认仅拦截 DROP/TRUNCATE/DELETE 首关键字**：复杂场景（如过程内嵌 DROP）不在拦截范围，属用户主动执行任意 SQL 的工具边界。
- Oracle 连接字符串 builder 命名空间为 `Oracle.ManagedDataAccess.Client`（包名为 `Oracle.ManagedDataAccess.Core`）。
