# Azrng.Core 结果包装与异常体系抽离建议

> 背景：T120 已将数据库主服务返回契约从元组统一为 `Azrng.Core.Results.IResultModel<T>` / `ResultModel<T>`。本文件记录当前仓库中可考虑上移到 `Azrng.Core` 包的通用能力，便于后续维护公共包时统一处理。

## 建议抽离项

### 1. ResultModel 创建与消息保真 helper

- 当前位置：
  - `AzrngTools/Services/Database/DatabaseResultModel.cs`
- 当前用途：
  - 统一创建 `IResultModel<T>` 成功 / 失败结果。
  - 保留调用方传入的成功消息，避免 `ResultModel<T>.Success(data)` 默认消息覆盖业务文案。
  - 将异常转换为失败结果时复用 `BaseException.ErrorCode`。
- 建议上移原因：
  - 这是通用应用层能力，不依赖数据库模块。
  - 多个业务服务都需要把业务结果和 Azrng 异常体系统一映射为 `IResultModel<T>`。
  - 可避免每个应用重复实现 `Success/Failure/FromException`。
- 建议 API 形态：

```csharp
public static class ResultModelFactory
{
    public static IResultModel<T> Success<T>(T data, string? message = null);
    public static IResultModel<T> Failure<T>(string message, string errorCode = "ERROR");
    public static IResultModel<T> FromException<T>(Exception exception, string? message = null);
}
```

- 注意事项：
  - 需要确认 `ResultModel<T>.Success(data)` 返回接口时是否稳定可安全强转到具体实现以写入 `Message`。
  - 如果公共包不希望依赖强转，建议在 `ResultModel<T>` 本身新增支持 message 的重载。

### 2. ResultModel 数据安全读取扩展

- 当前位置：
  - `AzrngTools/Services/Database/DatabaseResultModelExtensions.cs`
- 当前用途：
  - 为 `IResultModel<List<T>>` 提供 `DataOrEmpty()`，避免成功结果的 `Data` 可空声明污染调用方。
- 建议上移原因：
  - `IResultModel<T>.Data` 在 Nullable 场景下常被视为可空，列表结果尤其容易在调用方产生重复 `?? []`。
  - 这类扩展和业务无关，适合放到公共包。
- 建议 API 形态：

```csharp
public static class ResultModelExtensions
{
    public static IReadOnlyList<T> DataOrEmpty<T>(this IResultModel<IReadOnlyList<T>> result);
    public static List<T> DataOrEmpty<T>(this IResultModel<List<T>> result);
    public static T DataOrDefault<T>(this IResultModel<T> result, T defaultValue);
}
```

- 注意事项：
  - 返回 `IReadOnlyList<T>` 更通用，但为了兼容现有 `List<T>` 场景可保留双重重载。

### 3. 异常到结果的统一转换策略

- 当前位置：
  - `AzrngTools/Services/Database/DatabaseResultModel.cs`
- 当前用途：
  - 当异常为 `BaseException` 时使用 `ErrorCode`；普通异常使用默认错误码。
- 建议上移原因：
  - `BaseException`、`LogicBusinessException`、`ParameterException` 等本身已属于 `Azrng.Core`。
  - 异常体系和结果包装都在 `Azrng.Core` 中，转换策略也应由公共包提供。
- 建议 API 形态：

```csharp
public static class ResultModelExceptionExtensions
{
    public static IResultModel<T> ToFailureResult<T>(this Exception exception, string? message = null);
}
```

- 注意事项：
  - 需明确普通异常是否暴露原始 `Exception.Message`，桌面端可用，服务端 API 场景可能要隐藏内部细节。

## 暂不建议抽离项

### 数据库服务专用结果记录

- 当前位置：
  - `AzrngTools/Services/Database/DatabaseServiceResults.cs`
- 包含：
  - `DatabaseConnectionTestResult`
  - `DatabaseTableStatisticsResult`
  - `DatabaseSqlExecutionResult`
- 暂不抽离原因：
  - 这些类型直接表达数据库工作台业务返回结构，仍属于当前应用数据库模块。
  - 若未来 `Azrng.DataAccess` 提供统一数据库工作台服务契约，可再评估迁移到 `Azrng.DataAccess`，而不是 `Azrng.Core`。

## 建议后续步骤

1. 优先在 `Azrng.Core.Results.ResultModel<T>` 增加 `Success(T data, string message)` 重载，解决成功消息保真问题。
2. 在 `Azrng.Core.Results` 下新增通用 `ResultModelFactory` / `ResultModelExtensions`。
3. 在当前仓库替换 `DatabaseResultModel` 与 `DatabaseResultModelExtensions` 为公共包 API。
4. 对数据库模块执行一次构建和数据库相关测试，确认行为不变。
